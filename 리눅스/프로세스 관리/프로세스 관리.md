
## ps aux

```bash
$ ps aux
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.0 165784 11576 ?        Ss   12:42   0:00 /sbin/init
root           2  0.0  0.0   3180  2204 hvc0     Sl+  12:42   0:00 /init
brian        918  0.0  0.0   7492  3356 pts/2    R+   15:41   0:00 ps aux
```

- ps aux 로 프로세스 상태를 확인할 수 있음
- 각 프로세스는 어떤 이벤트가 발생할 때까지 cpu를 사용하지 않고 **sleep 상태**로 대기
	- **STAT 필드**
		- 첫 번째 글자가 S : 슬립 상태
		- 첫 번쨰 글자가 R : 실행 상태
		- 첫 번쨰 글자가 Z : 좀비 상태 (프로세스 종료했을 때)

### 모든 프로세스가 슬립 상태일 때

**아이들 프로세스** : 아무 일도 하지 않는 특수한 프로세스(아이들 프로세스)를 실행시켜 하나 이상의 프로세스가 '실행 상태'가 될 때까지 전력을 억제하면서 대기

## 프로세스 종료

1. 프로세스를 종료하려면 exit_group() 시스템 콜 호출
2. 커널에 프로세스가 사용한 자원 회수(메모리 등)

### 프로세스가 종료했을 때 얻을 수 있는 정보

**부모 프로세스는 wait() 나 waitpid() 같은 시스템 콜로 아래와 같은 정보를 얻음**
- 프로세스 반환값
	- 정상/비정상 종료 여부를 판정해서 에러 로그 출력 가능
- 시그널에 따라 종료했는지 여부
- 종료할때까지 얼마나 CPU시간을 사용했는지

#### 좀비 프로세스

> 자식 프로세스가 종료되었는데도, 부모 프로세스가 wait() 시스템 콜로 죽었는지 확인을 못했을 때의 상태인 프로세스

- 좀비 프로세스가 자원을 잡아먹지 않도록, 자식 프로세스 종료 상태를 제때 회수해야함

#### 고아 프로세스

> wait() 시스템 콜 실행 전에 부모 프로세스가 죽었을 때 해당하는 자식 프로세스의 상태

- init을 부모 프로세스로 지정 


## 시그널

> 커널이나 다른 프로세스가 특정 프로세스에게 보내는 비동기 알림
> 프로그램이 어떻게 죽는지 밖에서 통제하는 방식

- 프로세스를 제어할 유일한 수단
	- 실행 중인 프로그램에게 밖에서 제어하는 유일한 수단 (ctrl + c)

ex) ^C(SIGINT) , kill 명령어

|이름|번호|의미|
|---|---|---|
|SIGINT|2|Ctrl+C, 인터럽트|
|SIGQUIT|3|Ctrl+, 종료 + 코어 덤프|
|SIGKILL|9|강제 종료 (차단 불가)|
|SIGSEGV|11|잘못된 메모리 접근|
|SIGTERM|15|정상 종료 요청 (`kill` 기본값)|
|SIGSTOP / SIGCONT|19 / 18|정지 / 재개|
|SIGCHLD|17|자식 프로세스 상태 변화|
|SIGHUP|1|터미널 끊김 (데몬은 설정 리로드로 많이 씀)|

**시그널 핸들러**

프로세스를 실행하다가 시그널을 수신하면 실행 중인 처리를 중단하고, 핸들러에 등록된 처리를 수행하고 다시 이전에 하던 동작을 재개한다.

## 세션과 프로세스

**세션** : 프로세스 그룹들의 묶음이자, 하나의 터미널에 소속된 단위
- 터미널 하나를 세션 하나라고 볼 수 있음

**프로세스 그룹** : 시그널과 jobs 제어를 한 덩어리로 다루기 위한 묶음
- 셸에서 명령어를 치면 자식 프로세스들이 생성될 때 연관된 프로세스들을 묶어서 관리
- `cat log.txt | grep error` 
	- cat 과 grep은 각각 별개의 프로세스지만 동일한 하나의 프로세스 그룹으로 묶임

![[스크린샷 2026-07-28 143236.png]]

**포그라운드 프로세스 그룹**

> 여러 개의 프로세스 그룹 중에 키보드의 입력을 독점할 권한을 가진 오직 하나의 프로세스 그룹


- 세션당 하나만 존재
- 세션 단말에 직접 접근 가능
- 동기 방식과 비슷
	- 바로 키보드 입력 프롬프트를 가질 수 있는 상황을 부여받음
- 터미널마다 tpgid 라는 값이 있는데, 그 값과 자기 PGID가 같으면 포그라운드, 다르면 백그라운드임
- ps ajx 에서 STAT 필드에 +가 붙은 프로세스가 포그라운드 프로세스 그룹에 속함

**백그라운드 프로세스 그룹**

-  같은 세션에는 있지만 제어권을 부여받지 못한 나머지 모든 프로세스
- 키보드 입력 권한이 없음
- 비동기 방식과 비슷

## 데몬

> 시스템 시작부터 종료할 때까지 존재하며 실행되는 상주하는 프로세스

ex) sshd, nginx, dockerd

**특징**

- 터미널에서의 입출력이 불가능
- 다른 세션에 영향 받지 않도록 독자적인 세션을 가지고 있음
- ps ajx 에서 TTY 필드값이 '?'이고 PPID가 1인 프로세스들
### 필요한 이유

- 항상 대기해야 하는 프로세스 실행을 위해
- 여럿이 공유해야 하는 자원을 분배하여 일을 처리하기 위해
- 권한을 부여하기 위해

`systemctl` : 시스템을 컨트롤하는 명령어
- 데몬의 부모는 systemctl
